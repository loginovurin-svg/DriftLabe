# LogBox: сборка APK через GitHub Actions

В этой папке находится исходный Android-проект LogBox и готовый workflow для
сборки **debug APK arm64-v8a**. При обычном `push` в любую ветку GitHub Actions
сам установит Java и Android SDK, соберёт APK и проверит пакет, версию и
подпись. APK будет приложен к запуску workflow как артефакт.

## Загрузка в GitHub

1. Распакуйте этот архив.
2. Создайте пустой репозиторий на GitHub.
3. Загрузите **содержимое** распакованной папки в корень репозитория и отправьте
   первый `push`. Не загружайте только ZIP как один файл: GitHub не запустит
   workflow, пока файл `.github/workflows/build-logbox-apk.yml` не окажется
   в корне репозитория.
4. После `push` откройте вкладку **Actions**, выберите запуск `Build LogBox
   debug APK`, дождитесь успешного завершения и скачайте артефакт
   `LogBox-debug-arm64-v8a`.

## Что именно собирается

- Android application ID: `com.logbox` — отличается от оригинального Termux
  `com.termux`.
- Вариант bootstrap: `apt-android-7`.
- Версия исходников: `0.118.5` / versionCode `123`.
- Тип результата: debug APK, только ABI `arm64-v8a`.
- Подпись: общий тестовый ключ Termux из исходников; это **не release-ключ**.
- Release-сборка не настроена, приватный release keystore в архив не включён.

Чтобы комплект оставался компактным, четыре большие bootstrap-архива не
включены. Gradle скачивает нужные архивы для `apt-android-7`, сверяет их
контрольные суммы, затем запускает штатный
`scripts/patch-termux-bootstrap.py`, который подготавливает их для `com.logbox`.
Сеть на GitHub runner необходима.

APK, которые уже были в исходном handoff-архиве, в этот комплект не включены:
файл в разделе **Artifacts** появится только после отдельного успешного запуска
GitHub Actions. Сборка в этой рабочей сессии не запускалась.

## Изменение для совместимости Gradle

Wrapper настроен на Gradle 8.14.2, версию, указанную в передаче как
использованную при проверенной сборке. Исходный wrapper ссылался на Gradle
9.2.1 при Android Gradle Plugin 8.13.2, что не соответствует описанной
проверенной среде проекта.
